# GitHub 自动发布

仓库：https://github.com/winston-wen/ra2-flak-asmr

## 日常发布

除非明确指定保持或覆盖版本，每次更改默认递增补丁版本号。一次请求内的修复迭代只升级一次。同步修改 `src/AssemblyInfo.cs` 的两个版本号和 README；本地保留 `dist/<版本号>/RA2FlakASMR.exe`，并更新默认 EXE。当前版本为 **1.2.2**，包含原版炮声的随机音高、基础音量和素材强弱恢复。

```powershell
git add .
git commit -m "Describe the change"
git push origin main
```

每次推送 main 会运行 `.github/workflows/release.yml`：在 Windows runner 上构建单 EXE，运行混音、交互和像素对照检查，成功后创建 `build-<运行编号>` Release。Release 的 tag 指向实际构建的提交。

发布脚本从构建后的 EXE 自动读取版本号，写入 Release 标题与说明，避免手写发布版本与程序版本不同步。

工作流先创建带附件的草稿，再发布，避免发布只有标题、没有 EXE 的版本。重新运行同一次工作流使用原 tag 并替换附件，不额外生成重复版本。

要发布带版本号的版本：

```powershell
git tag v1.0.0
git push origin v1.0.0
```

推送标签时也会重新构建和验证，并发布名为 `v1.0.0` 的 Release。需要更改 Windows 文件属性中的版本号时，同时修改 `src/AssemblyInfo.cs`。

## 权限与设置

工作流使用 GitHub 自动提供的 `GITHUB_TOKEN` 和 `contents: write` 权限，不需保存个人令牌。仓库 / 组织策略需要允许 GitHub Actions 运行并授予该权限。PR 构建不会执行发布步骤。

若仓库启用了 immutable releases，已发布的同一个 Release 无法替换附件；此时使用新的提交或新标签发布。

首次克隆项目后若尚未设置远端：

```powershell
git remote add origin https://github.com/winston-wen/ra2-flak-asmr.git
git push -u origin main
```

普通 GitHub “Source code” ZIP 由 GitHub 自动生成；可运行版本请下载 Release 中的 `RA2FlakASMR.exe`。`SHA256SUMS.txt` 可用于核对完整性。

参考：[工作流触发](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow)、[GITHUB_TOKEN](https://docs.github.com/en/actions/tutorials/authenticate-with-github_token)、[GitHub CLI release create](https://cli.github.com/manual/gh_release_create)。
