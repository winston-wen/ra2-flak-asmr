# 油井进账与全局计数器

1.2.1 用户调整：进账声音量为 1.2.0 的一半；显示计数及可听节拍的间隔均乘以 1.25，分别为 20.833 ms 和 42.5 ms。以下原版取证中的 60 Hz 计数与 34 ms 声音服务是原版基准，不是当前生成器的数钱节奏。油井收入本身仍按 60 Hz 经济帧推进，不受这一节奏调整影响。

1.2.0 将油井收入送入一个玩家的余额与显示钱数计数器。不会给每座油井分配一个循环播放的音效。

## 本机原版核对

只读核对 Steam 安装目录中的 `game.exe`、`gamemd.exe` 和 MIX 内的规则、声音定义。原版 RA2、YR 及本机覆盖配置均为：

```ini
[CAOILD]
ProduceCashStartup=1000
ProduceCashAmount=20
ProduceCashDelay=100

[CreditUp]
Sounds=ucredup
Control=interrupt
Limit=1
Volume=20
```

Delay 单位是逻辑帧。油井机械循环声和抽杆动画使用独立机制，不是每抽一杆播放一次 CreditUp。本功能仅加入进账声。

本机 EXE 的计数逻辑可概括为：

```text
本帧所有收入先合并进 actual
若 actual > displayed：
    step = min(143, max(1, (actual - displayed) >> 3))
    displayed += step
    标记显示发生变化、方向为进账
本帧绘制金钱计数器时：
    若标记为进账，向全局声音管理器请求 CreditUp
    清除标记
```

例如，从追平状态单次进账 20、40、100、1000，分别需要 17、23、31、48 次显示更新。因此两座同时进账 40，触发的是一段 23 次更新的计数，不是两段各 17 次更新的声音叠加。

CreditUp 调用还传入 0.5 音量，和声音定义的 20% 合成为原版基准的 0.1 倍源幅度；1.2.1 按用户要求使用 0.05 倍。声音管理器按 `interrupt` / `Limit=1` 替换旧实例；本程序同样只保留一个进账声游标，但声音请求与实际播放之间还有独立的服务时钟。完整静态取证记录见 [计数与声音证据](research/credit-timing-evidence.txt)。也可参照 [Phobos 的计数步长说明](https://github.com/Phobos-developers/Phobos/blob/develop/docs/User-Interface.md#customize-the-step-limit-of-the-credits-indicator)。

## 声音服务节流与蜂鸣修复

进一步核对原版 EXE 发现，声音管理器并不是每个逻辑帧立即播放：RA2 的 `0x406EE2`、YR 的 `0x406FB2` 都先比较真实时间差，只有超过 `0x21`（33）毫秒才调用声音事件服务。YR 的时钟初始化将性能计数频率除以 1000，证实比较单位为毫秒。

旧实现遗漏了这一层，每次 60 Hz 钱数更新都立刻重启 ucredup，只播放约 16.67 ms 的开头后再次循环。重复的完全相同波形产生了用户听到的蜂鸣；1 ms 防爆音过渡不能消除这个周期循环。

1.2.0 蜂鸣修复后，钱数仍每逻辑帧更新，但声音请求先待处理；按原版 `elapsed > 33 ms` 条件，在理想连续轮询下每 34 ms 服务一次。同一个服务窗口中的 CreditUp 请求合并为一个，随后执行单声道替换。单笔 20 的收入保留 17 次计数请求，形成 8 次实际播放，声波可播放到 34 ms 后才被替换。原版调用时机或掉帧可能使服务更晚；这里不声称 34 ms 是所有实机录音的固定间隔。

本机 `audio.bag` 中 ucredup 的 IMA ADPCM 解码结果与项目原始 WAV 的全部 809 个采样完全一致，排除了音效文件取错或解码损坏。详细地址与回归证据见 [声音服务取证](research/credit-audio-service-evidence.txt)。

## 生成器采用的时钟与操作

- 经济时钟固定 60 逻辑帧/秒，每帧正好 800 个采样。1.2.1 的显示计数另按每 1000 个采样更新，即 48 次/秒；100 帧为 80000 个采样，约 1.667 秒。原游戏在不同速度下的现实时间会变化，不能把 100 帧理解为固定 100 ms。
- 增加数量视为新占领油井，立即记入每座 1000，首次定期收入在占领后 100 帧。一起添加的油井同期付款；后来添加的油井有自己的到期帧，不重置其他油井。
- 减少数量先移除后添加的油井，不扣已获得的钱；显示钱数继续追赶已有余额。
- 暂停冻结逻辑帧、到期时间和计数器，声音平滑淡出；恢复继续原状态，不重新记占领奖励。暂停时的数量修改在恢复后应用最终数量。
- 实际与显示余额使用 64 位整数，以支持长期生成。计数规则保持原版整数右移、最小步长和上限。

这是根据原版静态逻辑实现的独立模拟，不读取运行中的游戏。没有模拟开支、AI 玩家、帧跳过或模组注入后的自定义计数器；每帧一次绘制产生请求，再经独立声音服务合并；没有重现具体机器的帧跳过及调度抖动。

## 音频实现

原始 CreditUp 为 22050 Hz、809 个采样（约 36.69 ms）。只在启动时读取内嵌的 48 kHz PCM，不在进账时打开文件。源幅度保持原样，首尾加入 1 ms 过渡；打断前声时用 1 ms 连接上一输出采样和新声，避免人工切断带来的点击声。该过渡是本生成器的防爆音处理。

进账声在防空炮数量归一化之后、主音量与最终限幅之前合成。因此油井数量影响余额及计数持续时间，不会直接提高声音并发数或降低单声道音量。声音调度、计数器和定时付款都在现有音频线程内完成，不增加后台任务、UI 定时付款任务或跨线程锁。

## 验证

`test.ps1` 核对整数计数轨迹、每座油井到期时间、新增和移除、暂停恢复、仅油井输出、声音请求合并、声道替换次数、源音效后半段的逐采样保真，以及 64 防空单位 + 32 油井的限幅。四种回调长度生成的油井 PCM 按采样比较，避免回调分块影响进账节奏。1.2.1 的防空炮有意采用原版批处理及限额，约 461 万个 PCM 样本在不同回调长度间比较，另用独立逐采样参考器核对批处理声波。
